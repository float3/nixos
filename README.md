# Nix Configs

## NixOS Hosts

Switch the current NixOS machine:

```sh
sudo nixos-rebuild switch --flake .#$(hostname)
```

Build or deploy a specific host:

```sh
nix build .#nixosConfigurations.thinkcentre.config.system.build.toplevel
nixos-rebuild switch --flake .#thinkcentre --target-host root@thinkcentre
```

Available NixOS hosts:

- `workstation`
- `laptop`
- `hetzner`
- `localserver`
- `macbook`
- `steamdeck`
- `thinkcentre`
- `wsl`

## Nix-on-Droid

This repo has a Nix-on-Droid target at `.#nixOnDroidConfigurations.default`.
This is for running Nix inside the Nix-on-Droid Android app, not for building a
GrapheneOS system image.

On the phone:

```sh
# Install Nix-on-Droid from F-Droid first, then clone this repo inside the app.
nix-on-droid switch --flake .#default
```

From another machine you can sanity-check evaluation with:

```sh
nix build .#nixOnDroidConfigurations.default.activationPackage --no-link --impure
```

The `--impure` flag is expected for local flake builds because nix-on-droid
release 24.05 still uses hardcoded `proot` store paths during activation. A
local x86_64 build may also stop at Android-only dependencies such as
`proot-termux-static-aarch64-unknown-linux-android`; the real target is the
aarch64 Nix-on-Droid environment on the phone.

`thinkcentre` is a kiosk profile. Before installing it on the real machine, replace the placeholder filesystem labels in `nixos/hosts/thinkcentre/hardware-configuration.nix` with the identifiers generated by `nixos-generate-config`.

The kiosk behavior lives in `nixos/roles/kiosk.nix`, so another host can reuse it by importing that role and setting:

```nix
float3.kiosk = {
  enable = true;
  url = "https://example.com";
};
```

## Home Manager

Home Manager is wired into each NixOS host through the flake, so `nixos-rebuild switch --flake .#workstation` also applies `home/base.nix`, `home/linux.nix`, and desktop modules where configured.

Standalone Home Manager entry points are also available:

```sh
home-manager switch --flake .#hill
home-manager switch --flake .#macbook
```

Use `.#hill` for a generic Linux account and `.#macbook` for the MacBook. The MacBook profile is currently standalone Home Manager on `aarch64-darwin`; for an Intel MacBook, change the `macbook` system in `flake.nix` to `x86_64-darwin`.

## Headroom

Headroom for Codex is available as a project-local flake in `./headroom`.

```sh
nix develop ./headroom
headroom doctor
headroom wrap codex
headroom proxy --port 8787
```

The first `nix develop` creates `headroom/.venv` and installs
`headroom-ai[all]` there with `uv`. Set `HEADROOM_UPDATE=1` when entering the
shell to refresh the package.

## Formatting And CI

This repo uses Alejandra:

```sh
nix develop --command alejandra --check .
nix develop --command alejandra .
```

CI runs formatting, `nix flake check`, and derivation-path evaluation for each NixOS host plus both standalone Home Manager profiles.

## Secrets

The normal user password hash is intentionally not stored in this repository. Create it on each NixOS machine before switching:

```sh
sudo install -d -m 0700 /etc/nixos/secrets
mkpasswd -m yescrypt | sudo tee /etc/nixos/secrets/hill.hashed-password >/dev/null
sudo chmod 0600 /etc/nixos/secrets/hill.hashed-password
```

The Hetzner Nextcloud host also expects:

```sh
sudo install -d -m 0700 /etc/nixos/secrets
sudoedit /etc/nixos/secrets/nextcloud-admin-pass
sudo chmod 0600 /etc/nixos/secrets/nextcloud-admin-pass
```

Root password login is locked. Root SSH key login remains enabled for existing deploy flows, but password authentication is disabled.
